# decision-tree-2

Drug200 — классификация подходящего лекарства (дерево решений + Random Forest)

Проект по классификации пациентов на один из пяти препаратов (drugA, drugB, drugC, drugX, drugY) на основе возраста, пола, давления, уровня холестерина и соотношения натрия к калию в крови. Расширенная версия анализа: помимо базового дерева решений, здесь визуализируется структура дерева, исследуется влияние гиперпараметров на качество модели и добавлено сравнение со случайным лесом (RandomForestClassifier).

Описание

Датасет drug200.csv содержит 200 наблюдений без пропусков: демографические и клинические показатели пациента вместе с меткой препарата, который ему подошёл. Ноутбук drugs2.ipynb кодирует категориальные признаки, обучает и визуализирует несколько вариантов дерева решений с разными гиперпараметрами, а затем сравнивает результат со случайным лесом.

Что делает ноутбук
1. Загрузка и подготовка данных
Чтение drug200.csv через pandas.
Категориальные признаки Sex, BP, Cholesterol закодированы через LabelEncoder.
Признаки (x) и целевая переменная Drug (y) разделены на обучающую и тестовую выборки (train_test_split, test_size=0.25, random_state=42).
2. Базовое дерево решений

Обучен DecisionTreeClassifier(criterion='entropy', max_depth=3, random_state=42).

Accuracy: 0.88

Структура дерева визуализирована через tree.plot_tree() с подписанными признаками и классами.
3. Эксперименты с гиперпараметрами дерева

Последовательно обучено и визуализировано ещё три варианта дерева, чтобы показать, как гиперпараметры регуляризации влияют на качество:

Параметры	Accuracy
criterion='entropy', max_depth=3 (базовый)	0.88
min_impurity_decrease=0.1	0.82
min_samples_split=5, max_depth=2	0.82

Каждый вариант сопровождается визуализацией дерева (tree.plot_tree), наглядно показывающей, как ограничение глубины (max_depth) или минимального прироста информации (min_impurity_decrease) «обрезает» дерево и снижает точность на тестовой выборке, тогда как дерево без ограничений идеально подгоняется под тестовую выборку (accuracy = 1.0).

4. Random Forest

Обучен RandomForestClassifier(n_estimators=20) для сравнения с одиночным деревом.

Accuracy: 0.98

Важное замечание о точности 1.0

Дерево без ограничений (min_impurity_decrease=0.0) показывает accuracy = 1.0 на тестовой выборке — это, скорее всего, результат переобучения (overfitting) на небольшом датасете (всего 200 наблюдений, 150 из которых — обучающая выборка), а не признак действительно идеальной модели. На новых, не встречавшихся в обучении данных такое дерево, вероятнее всего, будет работать заметно хуже. Для честной оценки стоит использовать кросс-валидацию (cross_val_score, уже импортирован, но не используется) вместо единственного разбиения на train/test.

Возможные улучшения
Оценить все модели через k-fold кросс-валидацию (cross_val_score), а не по одному разбиению train/test — особенно важно для дерева без ограничений глубины, где высок риск переобучения.
Переменная LabelEncoder переприсваивается экземпляром и затирает исходный класс sklearn.preprocessing.LabelEncoder в области видимости — лучше использовать отдельные имена (le_sex, le_bp, le_chol) и сохранять кодировщики для инференса на новых данных.
BP — признак с естественным порядком (LOW < NORMAL < HIGH), но LabelEncoder кодирует его по алфавиту без учёта порядка — лучше использовать OrdinalEncoder с явно заданным порядком категорий.
Учесть дисбаланс классов (drugB/drugC — по 16 против drugY — 91): использовать стратифицированное разбиение (stratify=y) и метрики, устойчивые к дисбалансу (classification_report, f1_score с average='macro').
Зафиксировать random_state во всех моделях (в блоках с min_samples_split=5, max_depth=2 и RandomForestClassifier он не задан) — иначе результаты будут не воспроизводимы от запуска к запуску.
Подобрать оптимальные гиперпараметры дерева и леса через GridSearchCV/RandomizedSearchCV вместо ручного перебора отдельных комбинаций.
Сохранить лучшую модель (например, RandomForestClassifier с accuracy 0.98) через joblib/pickle для дальнейшего использования без повторного обучения.
